# 답안 저장·복습 신뢰성 검증

## 변경 내용

1. 화면의 정답 수·재출제·복습 일정은 서버 채점 결과로 확정한다. 실패 응답에 콤보·보상을 추정하지 않는다.
2. 객관식과 입력형 복습 모두 답안 및 필요한 복습 저장 확인 전 다음 문제로 넘어가지 않는다. 입력형 오답의 자동 이동도 응답 이후 시작한다.
3. 한 제출의 요청 식별자·답안·힌트·세션 시작 여부를 고정한다. 전송 실패는 같은 요청으로 재시도하고, 채점은 성공했지만 복습 저장만 실패했으면 채점을 다시 호출하지 않는다.
4. 복습 일정은 데이터베이스 저장 성공 후 로컬에 확정한다. 첫 결과 기록 실패를 성공으로 처리하지 않는다.
5. 15초 제한 시간, 늦은 응답·사용자 변경 보호, 중복 제출·빠른 연속 이동 방지, 오류 안내·재시도 초점, 작은 화면에서 선택 답의 표시 위치를 보강했다.
6. 예약 출석 작업은 최신 함수 참조를 사용하고 반복 예약까지 해제한다. 출석 시각·보상 조건은 그대로다.

## 서버 계약

기존 `submit_quiz_answer`는 보상·경험치·미션·일 150회 조건을 그대로 두고 프로필 행 잠금만 보강했다. 구형 171번 호출 형식도 유지한다. 새 `submit_quiz_answer_once`는 동일 사용자·요청 식별자의 결과를 한 번만 만들고 원문 답안 대신 지문을 보관한다. 재요청은 재지급 없이 기존 채점 결과와 현재 잔고·경험치·미션·콤보를 반환한다. 기록 테이블의 일반 역할 직접 접근은 차단했다.

마이그레이션과 복구는 검토 함수의 지문 및 구조를 확인한다. 복구는 새 호출 클라이언트를 먼저 내린 뒤 수행하며, 기존 요청 기록은 삭제하지 않는다.

## 실행한 검사

- 전체 자동 검사 **599개 통과**, 린트 오류·경고 0건, 타입 검사·앱 빌드 통과.
- 기존 표 렌더링 검사 1개가 과도한 동시 작업 중 5초 제한에 걸려, 제한 시간을 늘리는 대신 검사 작업자를 2개로 제한했다. 이후 전체 599개를 다시 통과했다.
- 운영의 실제 함수와 가상 프로필을 이용해 중복 요청, 잘못된 요청, 늦은 재요청, 객관식·힌트·오답, 150/151회 경계 및 접근권한을 검사한 뒤 전부 취소했다. 새 테이블·함수 제거와 기존 함수 원복을 확인하고 그 후 서버 보강을 적용했다.
- 공개 경로에서 프로필 없는 제출은 SQLSTATE 28000으로, 기록 직접 조회는 42501로 차단됨을 확인했다.
- 독립 PostgreSQL 16의 실제 동시 세션 20개(같은 요청)와 30개(다른 요청) 검사를 통과했다. 중복 지급 없음·상태 직렬화·원문 변경 감지·권한 차단·복구·재적용·기록 보존을 확인했다.
- 자동 검사 근거: https://github.com/yyoujg/moneytermi/actions/runs/39176191198 (검사 브랜치의 앱 업로드 작업은 건너뜀). 이 독립 환경의 보상 보조 함수는 대역이며, 실제 보상 규칙 검증은 앞의 운영 취소 검사와 원본 함수 대조로 구분한다.
- 320×568에서 객관식 오류 안내·선택 답·재시도 버튼·학습 카드 이동 버튼이 화면 안에 있고 가로 넘침이 없음. 같은 답 재전송 후 정답·서버 보상 표시를 확인했다.
- 390×844 다크 모드에서 복습 저장 실패 시 입력·힌트·건너뛰기가 잠기고, 재저장 후 정상 진행함을 확인했다. 화면 검사는 실제 컴포넌트와 모의 계정·응답을 사용했으며 실제 계정·데이터베이스·보상을 동작시키지 않았다.

## 남은 범위와 출시 주의

실제 아이폰의 토스 앱·광고·알림·프로모션 수령까지 포함하는 기기 통합 검증은 이번 모의 화면 검사와 다르다. 외부 검수 승인도 별도다. 기존 171번 검수 요청을 임의 취소하거나 수정본을 자동 출시하지 않는다. 서버 보강을 먼저 적용하고 새 호출 클라이언트는 검증·빌드 이후 업로드한다.

빌드에는 기존의 큰 외부 라이브러리 묶음 경고가 남아 있으며, 경고 기준을 올려 숨기지 않았다.
