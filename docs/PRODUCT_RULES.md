# 머니터미 학습과 측정 기준

2026-10-16 로컬 구현 기준. 운영 반영일은 출시 후 RELEASE_NOTES의 기능 도달일에 기록한다.

## 서비스 목적과 진입

경제 표현이 궁금한 사용자가 필요한 주제를 골라 설명을 읽고, 준비된 문제로 이해를 확인한 뒤 다시 떠올리도록 돕는다.

- 주제는 레벨과 카테고리의 조합이다. 다른 주제의 완료 여부와 관계없이 시작할 수 있다.
- 선택한 주제 안에서는 기존 코스 순서와 3~5개 용어 레슨 순서를 유지한다.
- 홈 상단에 오늘 다시 볼 용어와 새 학습 진입을 둔다. 이어 배우기는 마지막으로 시작한 주제의 미완료 레슨을 우선한다.
- 주제의 누적 복습은 그 주제에서 앞서 살펴본 용어를 대상으로 한다.

## 완료 기준

| 구분 | 근거 | 표시와 제한 |
|---|---|---|
| 살펴봄 | 카드 설명 확인, 기존 열람 기록 | 코스 진도에 사용. 이해나 실생활 판단 능력을 보증하지 않음 |
| 이해 확인 | 해설이 있는 전용 상황 문제의 답변 | 해당 세션의 정답 개수 표시. 첫 풀이와 재풀이를 구분 |
| 기억 확인 | 예정일이 된 용어의 복습 답변 | 첫 시도 정답 개수 표시. 재시도 정답을 합산하지 않음 |

퀴즈를 풀지 않아도 읽기 진도를 계속할 수 있다. 기존 `known` 상태와 SRS의 `unknown` 상태를 모두 열람 이력으로 취급하므로, 복습 오답 때문에 코스가 다시 잠기지 않는다. 이해 확인 성적은 현재 세션과 분석 이벤트로 구분하며 별도 숙련도 이력을 서버에 신설하지 않는다.

## 비용과 중단 후 이어하기

- 레슨 시작 포인트 차감 없음. 잔고 0P에서도 시작 가능.
- 새 레슨과 코스 퀴즈를 처음 시작할 때 에너지 1 사용.
- 완료 레슨 재열람, 레슨 직후 확인, 학습 전 복습, 코스 복습, 오늘 다시 보기는 추가 비용 없음.
- 에너지 최대 25, 1시간에 1 회복. 600P 전체 충전과 광고 충전은 선택 사항.
- 시작 기록은 프로필별 기기 저장소의 에너지 상태와 함께 보존한다. 같은 노드와 용어 구성이면 미완료 재진입도 추가 차감하지 않는다.
- 시작 기록의 기기 간 동기화는 제공하지 않는다. 기기 저장소를 지운 경우 미완료 레슨은 다시 차감될 수 있다. 서버에 남은 열람 진도는 유지한다.
- 포인트는 선택한 에너지 충전과 XP 부스트에 사용한다. 기존 보상과 서버 잔고는 변경하지 않는다.

## 상황 문제와 콘텐츠 운영

카드 열람 후 `lessonCheck: true`이며 해설이 있는 기존 전용 문제를 우선 연결한다. 없는 레슨은 용어 퀴즈로 연결하며, 상황 적용 문제는 준비 중이라고 안내한다. 모든 레슨에 적용 문제가 갖춰졌다고 홍보하지 않는다.

신규 또는 개정 레슨의 콘텐츠 완료 조건:

1. 해당 레슨의 상황 적용 문제 최소 1개. 용어 이름 찾기 외에 변화, 비교 또는 추가 확인 조건을 묻는다.
2. 정답 1개와 이유를 설명하는 해설. 예시의 가정과 적용 범위 명시.
3. 출처 URL 또는 문서명, 기준일, 검토일, 검토 담당을 콘텐츠 변경 기록에 남긴다.
4. 법률, 세금, 대출 요건 등 변동 정보는 현재 공식 근거를 재확인하고 예외 조건을 기재한다.
5. 문제와 해설 검토, 화면 확인, 데이터 반영 확인을 각각 완료한 뒤 공개한다.

2026-10-16 후속 점검에서 상황 문제 221개를 운영 DB에 추가했고, 현재 코스의 320개 레슨 모두 해설이 있는 상황 문제를 갖는 것을 확인했다. 문항에는 사례 분류와 계산 문제가 포함된다. 기존 카드 본문 전체의 외부 사실 검증은 별도다. 적용 범위와 운영 지표는 [전체 레슨 문항과 운영 지표 점검](CONTENT_AND_METRICS_20261016.md)을 따른다.

## 분석 이벤트

| 이벤트 | 주요 필드 | 의미 |
|---|---|---|
| `lesson_start` | `course_id`, `node_id`, `total`, `revisiting` | 진입 조건을 통과한 레슨 시작 |
| `lesson_view_complete` | `course_id`, `node_id`, `total` | 설명 카드 열람 완료 |
| `lesson_check_start` | `course_id`, `node_id`, `total` | 전용 상황 문제 시작 |
| `lesson_check_answer` | `word_id`, `correct`, `attempt`, 코스와 노드 | 상황 문제 답변. `attempt=1`이 첫 풀이 |
| `lesson_check_complete` | `total`, `correct`, `attempt`, 코스와 노드 | 상황 문제 세트 완료 |
| `quiz_start` | `mode`, `total`, 코스와 노드 | 퀴즈 또는 복습 세트 시작 |
| `quiz_answer` | `mode`, `word_id`, `correct`, `first_attempt` | 첫 답변과 재시도 구분. 주관식은 `used_hint`도 기록 |
| `quiz_complete` | `mode`, `total`, `correct`, `attempts` | `total`은 원래 문제 수, `correct`는 첫 시도 정답 수, `attempts`는 재시도 포함 제출 수 |
| `review_start` | `source`, `count` | 홈 또는 퀘스트의 복습 진입 버튼 클릭 |
| `energy_blocked` | `type`, `energy`, `node_id`, `course_id` | 에너지 부족으로 진입하지 못함 |

`mode`: `lesson_recall`은 열람 직후 용어 확인, `lesson_warmup`은 학습 전 복습, `course_quiz`는 코스 퀴즈, `course_review`는 코스 복습, `review`는 예정일 복습, `quiz`는 기타 진입이다. 상황 문제는 `lesson_check_*`로 분리한다.

출시 전후 `quiz_complete`의 분모 정의가 다르므로 기능 도달일로 나눠 분석한다. 시작 이벤트는 완료나 이해의 증거로 사용하지 않는다. 첫 카드 클릭을 기록하는 기존 `activation_first_card`는 열람 보조 지표로만 쓴다.

## 성과 측정

- 활성화: 신규 사용자 중 첫 상황 문제 세트를 완료한 사용자 비율. 전용 문항이 있는 레슨 진입 비율도 함께 보고, 콘텐츠 미비와 UX 이탈을 구분한다.
- D1 학습 재방문: 신규 방문일 다음 한국 날짜에 카드 열람 완료 또는 문제 답변을 한 사용자 비율. 단순 앱 열기와 구분한다.
- 기억: `mode=review`, `first_attempt=true`인 답변의 정답률. 힌트 사용 여부를 함께 구분한다.
- 진입 제한: 에너지 부족을 경험한 사용자 수와 같은 세션에서 학습을 재개하지 않은 비율. 무료 복습 전환도 별도로 집계한다.
- 모든 수치는 기간, 신규 코호트, 유입 경로, 앱 버전, 분자와 분모 인원을 함께 보고한다. 기존 문서의 과거 잔존율을 현재 기준선으로 사용하지 않는다.

콘솔 이벤트 수신과 집계 가능 필드를 확인한 뒤 출시 전후를 비교한다. 앱 코드의 이벤트 추가만으로 운영 지표가 개선됐다고 판단하지 않는다.

## 반복 방문과 안내

- 리뷰 요청은 예정일 복습을 끝내고 첫 시도 정답이 있는 때에만 호출한다. 실제 노출 여부는 플랫폼이 결정한다.
- 첫 카드 확인과 미션 보상 수령 시에는 리뷰를 요청하지 않는다.
- 미션은 한국 시간 0시, 8시, 16시에 초기화한다. 종류와 보상은 서버 정의를 따른다.
- 현재 탭은 홈, 퀘스트, 리그, 마이. 오늘 복습은 홈과 퀘스트에서 진입한다.
